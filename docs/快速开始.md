# 快速开始

## 准备

| 软件 | 版本 | 用途 |
|---|---|---|
| JDK | 21 | 编译与运行 |
| Maven | 3.9+ | 构建 |
| Docker | 含 compose v2（`docker compose version` 可用） | 中间件、镜像构建；`mvn test` 也用它启动 MySQL 与 Redis |

端口、账号与密钥都在 `docker/.env` 中，均为开发默认值。

## 方式一：一键启动全部

```bash
scripts/docker-up.sh
```

脚本依次：

1. `mvn clean package` 打包 gateway、system、member、monitor；
2. 构建四个应用镜像，启动中间件与应用，等待全部健康检查通过（最多 8 分钟）；
3. 打印各控制台地址。

首次启动时，MySQL 容器自动执行 `sql/mysql/ccloud.sql` 与 `docker/mysql/init/` 下的脚本：
创建 `ccloud`、`nacos`、`xxl_job` 三个库，登记 XXL-Job 执行器与任务，并按 `.env` 设置 XXL-Job 管理员密码。
一次性容器 `ccloud-nacos-init` 按 `.env` 初始化 Nacos 管理员账号，并导入 `docker/nacos/config/` 下的配置包。

启动后先用管理员登录验证（见 [README](../README.md#接口与鉴权) 的示例），再打开 http://127.0.0.1:48080/doc.html 浏览接口文档。

停止：

```bash
scripts/docker-down.sh
```

默认保留数据卷；加 `--purge` 同时删除数据，下次启动重新初始化数据库。

验证编排是否正常：

```bash
scripts/verify-docker.sh --full
```

## 方式二：只启动中间件，在 IDE 中运行服务

```bash
scripts/docker-up.sh middleware
```

启动 MySQL、Redis、Nacos、Zipkin、XXL-Job，并初始化数据库与 Nacos。然后在 IDE 中以 `local` profile（默认）运行：

| 启动类 | 端口 |
|---|---|
| `com.ccloud.module.system.SystemServerApplication` | 48081 |
| `com.ccloud.module.member.MemberServerApplication` | 48083 |
| `com.ccloud.gateway.GatewayServerApplication` | 48080 |
| `com.ccloud.monitor.MonitorServerApplication`（可选） | 48182 |

`local` profile 连接本机的中间件（MySQL `127.0.0.1:3306`，账号 `root / root123`；Redis `127.0.0.1:6379`；Nacos `127.0.0.1:8848`），
与 `docker/.env` 的默认值一致；关闭了登录验证码与 XXL-Job 执行器，便于调试。建议先启动 system：member 启动后经 RPC 从 system 加载国际化文案，system 未就绪时只记录警告，等 5 分钟后的定时刷新再加载。

若修改过 `docker/.env` 中的端口或密码，运行服务时用同名环境变量覆盖，例如 `MYSQL_PORT`、`MYSQL_PASSWORD`、`NACOS_ADDR`。

## 方式三：从源码构建

```bash
mvn clean package -DskipTests
```

各应用的可执行 jar：

- `ccloud-gateway/target/ccloud-gateway.jar`
- `ccloud-monitor/target/ccloud-monitor.jar`
- `ccloud-module-system/ccloud-module-system-biz/target/ccloud-module-system-biz.jar`
- `ccloud-module-member/ccloud-module-member-biz/target/ccloud-module-member-biz.jar`

运行时用 `SPRING_PROFILES_ACTIVE` 选择环境（`local` / `dev` / `prod`）。`prod` 不提供密码与密钥的默认值，须通过环境变量提供：

- 数据库与 Redis 的地址与密码、`CCLOUD_ENCRYPT_KEY`（字段加密）、`CCLOUD_MONITOR_PASSWORD`（监控面板）、
  `CCLOUD_CORS_ALLOWED_ORIGIN_PATTERNS`（网关允许的前端来源）——缺失时对应服务启动失败；
- `CCLOUD_INTERNAL_SIGN_SECRET`（网关与各服务共享的内部签名密钥）——网关缺失时启动失败；业务服务缺失时仍能启动，
  但会拒绝全部内部身份，所有登录请求都变成未登录。网关、system、member 必须配置同一个值。

运行测试：

```bash
mvn test
```

测试以 Testcontainers 启动真实的 MySQL 8.4 与 Redis 7，需要本机 Docker 可用。

## 校验脚本

| 脚本 | 校验内容 |
|---|---|
| `scripts/verify-deps.sh` | 依赖版本一致性 |
| `scripts/verify-framework.sh` | 框架层不反向依赖业务模块 |
| `scripts/verify-sql.sh` | 全量 SQL 脚本与初始化数据 |
| `scripts/verify-docker.sh` | compose 编排、数据库与 Nacos、XXL-Job 初始化；`--full` 端到端 |
| `scripts/verify-nacos.sh` | Nacos 配置包导入与读回；`--full` 校验优先级与即时生效 |
| `scripts/verify-docs.sh` | 本文档与 README 的必备内容、引用与端口 |
| `scripts/verify-e2e.sh` | P1 端到端验收：经网关的三端登录、按钮权限、SSO、令牌、安全边界、文档、链路追踪、监控、定时任务（需先启动全部服务） |
| `scripts/verify-all.sh` | 依次执行以上全部校验（含构建与启动全部服务），任一失败即中止；加 `--with-tests` 先执行 `mvn test` |
