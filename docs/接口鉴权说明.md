# 接口与鉴权说明

## 请求链路

```
客户端 ──► 网关 ─────────────────────────────────────────────► 业务服务
          1. 拒绝路径穿越与歧义编码（/..、%2F、;）             5. 验证内部身份头签名与时效
          2. /rpc-api/** 一律 403                              6. 按路径校验用户类型（admin-api 只认管理员）
          3. 剥离外部携带的内部身份头                           7. 校验租户（令牌租户与请求租户一致、租户有效）
          4. 校验令牌（调 system，缓存 60 秒）并写入内部身份头   8. @PreAuthorize 按钮级权限、部门数据权限
```

网关与业务服务之间以内部身份头传递登录用户，签名密钥 `CCLOUD_INTERNAL_SIGN_SECRET` 由双方共享。
业务服务只认验签通过的身份，直接访问业务服务并伪造身份头是无效的。

## 通用约定

| 请求头 | 说明 |
|---|---|
| `Authorization: Bearer {accessToken}` | 访问令牌，登录接口返回 |
| `X-Tenant-Id` | 租户编号。匿名接口必须携带；已登录请求由网关按令牌中的租户设置，请求自带的值会被覆盖 |
| `Accept-Language` | `zh-CN`（默认）或 `en-US`，决定错误提示的语言 |

响应统一为 `{"code": 0, "msg": "", "data": ...}`，`code` 为 0 表示成功。常见错误码：

| code | 含义 |
|---|---|
| 401 | 未登录、令牌无效或已过期；开放接口签名校验失败 |
| 403 | 没有该操作权限；访问内部接口；登录用户访问其他租户的数据；开放接口：调用方 IP 不在应用白名单内、应用未获授权调用该接口 |
| 429 | 请求过于频繁（网关限流），响应头 `Retry-After` 为建议等待秒数 |
| 503 | 认证服务或下游服务暂不可用，可稍后重试；开放接口调用时为开放平台服务暂不可用。**不要当作 401 处理而清除登录态** |

## 管理端 admin-api

| 接口 | 说明 |
|---|---|
| `POST /admin-api/system/auth/login` | 账号密码登录，`{"username","password"}`，可带 `tenantName` 按租户名登录 |
| `POST /admin-api/system/auth/sms-login` | 短信验证码登录，先调 `send-sms-code` |
| `POST /admin-api/system/auth/refresh-token?refreshToken=` | 刷新令牌 |
| `POST /admin-api/system/auth/logout` | 登出，作废当前令牌 |
| `GET /admin-api/system/auth/get-permission-info` | 当前用户、角色、权限标识与菜单树，前端据此渲染菜单与按钮 |
| `PUT /admin-api/system/user/profile/update-avatar` | 个人中心上传头像（multipart，字段 `avatarFile`，需登录） |
| `POST /admin-api/infra/file/upload` | 上传文件（multipart，字段 `file`），返回访问地址；登录即可，类型按内容识别，HTML / SVG / 脚本一律拒绝，默认上限 10MB |
| `GET /admin-api/infra/file/{configId}/get/**` | **匿名可读**：读取数据库或本地磁盘存储的文件，不需要令牌和租户头；S3 存储的文件由存储桶直接读取，经此接口一律 404。路径含内容哈希，只有知道地址才能读到；响应带 `X-Content-Type-Options: nosniff` |
| 参数配置 `/admin-api/infra/config/` 的 `create`、`update`、`delete`；文件配置 `/admin-api/infra/file-config/` 的 `create`、`update`、`update-master`、`delete`、`test`；消息死信 `/admin-api/infra/message-dead-letter/*` 全部接口 | **仅限系统租户**（套餐 0 的租户）。参数配置与文件配置为全部租户共用，死信跨租户，普通租户调用返回错误码 `1002008000`，即使其套餐含这些菜单也一样。参数配置与文件配置的读取不受此限 |
| 接口目录 `/admin-api/open/api/` 的 `create`、`update`、`delete` | **仅限系统租户**。接口目录为全部租户共用，普通租户调用返回错误码 `1005000000`，即使其套餐含该菜单也一样；开放应用、调用日志、回调日志按租户隔离，由各租户管理员自管 |

```bash
curl -s -X POST http://127.0.0.1:28080/admin-api/system/auth/login \
  -H 'Content-Type: application/json' -H 'X-Tenant-Id: 1' \
  -d '{"username":"admin","password":"admin123"}'
```

管理端令牌有效期 30 分钟，刷新令牌 30 天（OAuth2 客户端 `ccloud-web`，见 `sql/mysql/dml/05-oauth2-client.sql`）。
密码连续输错 5 次锁定 10 分钟。生产环境默认开启图形验证码，登录时需带 `captchaUuid`、`captchaCode`。

## 开放接口 open-api

第三方系统以应用身份调用，按请求签名认证，不使用登录令牌。

| 请求头 | 说明 |
|---|---|
| `X-Open-App-Id` | 应用编号（AppKey） |
| `X-Open-Timestamp` | 毫秒时间戳，与服务器时间相差不超过 5 分钟 |
| `X-Open-Nonce` | 随机串，不超过 64 个字符，10 分钟内不可重复 |
| `X-Open-Sign` | 签名，见下文 |

```
签名串 = 请求方法 + "\n"
       + 原始路径（URL 编码后的形式，不含查询串）+ "\n"
       + 原始查询串（URL 编码后、与实际发送的完全一致，没有则为空串）+ "\n"
       + X-Open-Timestamp + "\n"
       + X-Open-Nonce + "\n"
       + 请求体的 SHA-256，十六进制小写（没有请求体时为空字节的摘要）
X-Open-Sign = Base64( HmacSHA256(key = appSecret, data = 签名串) )
```

请求体参与签名，防止截获请求的人篡改参数；查询串不做排序，按实际发送的原样参与签名。Java 示例：

```java
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.util.Base64;
import java.util.HexFormat;
import java.util.UUID;

public final class OpenApiSigner {

    public static String sign(String appSecret, String method, String rawPath, String rawQuery,
                              long timestamp, String nonce, byte[] body) throws Exception {
        String bodyHash = HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(body));
        String stringToSign = method + "\n" + rawPath + "\n" + (rawQuery == null ? "" : rawQuery) + "\n"
                + timestamp + "\n" + nonce + "\n" + bodyHash;
        Mac mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(appSecret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        return Base64.getEncoder().encodeToString(mac.doFinal(stringToSign.getBytes(StandardCharsets.UTF_8)));
    }

    public static void main(String[] args) throws Exception {
        long timestamp = System.currentTimeMillis();
        String nonce = UUID.randomUUID().toString();
        byte[] body = "{\"amount\":100}".getBytes(StandardCharsets.UTF_8);
        String sign = sign("ccloud-open-demo-secret", "POST", "/open-api/pay/order/create", null, timestamp, nonce, body);
        // 请求头：X-Open-App-Id: ccloud-open-demo、X-Open-Timestamp: timestamp、X-Open-Nonce: nonce、X-Open-Sign: sign
        System.out.println(sign);
    }
}
```

### 应用的创建与管理

应用在管理后台 开放平台 → 开放应用 中创建（`POST /admin-api/open/app/create`，权限 `open:app:create`）。创建时系统生成 16 位 AppKey 与 32 位随机密钥：

- **密钥只在创建与「重置密钥」时返回一次**，库中加密存储，之后查询一律显示掩码（前 4 位 + `****` + 后 4 位）。丢失只能重置，旧密钥立即作废；
- 应用可设置状态（开启 / 关闭）、过期时间、每秒请求上限（1–10000）、IP 白名单、回调地址、联系人；AppKey 不可修改；
- 应用只能调用**已授权**的接口：管理员在「可调接口」中勾选（只能选已开启的接口）。接口目录由系统租户维护，每个接口是一条「请求方法 + 路径」，网关按**方法与原始路径精确匹配**，不支持通配；
- 应用、授权、密钥的任何变更，网关立即生效（open 经 Redis 广播使各网关实例的缓存失效；广播丢失时最多延迟 60 秒）。

每个应用有独立的限流配额（每秒请求数，令牌桶，超出返回 429），伪造签名的请求不消耗配额。验签通过后，网关以应用所属租户设置 `X-Tenant-Id`，并以开放应用身份（用户类型 3）转发：业务服务只在 `/open-api/**` 下接受这种身份，它不能调用管理端与用户端接口。

### 网关校验顺序与错误

| 顺序 | 校验 | 失败结果 |
|---|---|---|
| 1 | 四个签名请求头齐全，nonce 不超过 64 个字符 | 401 |
| 2 | 应用存在、已开启、未过期 | 401；开放平台服务不可用且网关没有缓存时 503 |
| 3 | 调用方 IP 在白名单内（白名单为空表示不限制） | 403 |
| 4 | 时间戳与服务器相差不超过 5 分钟，请求体不超过 1MB，签名正确 | 401；请求体过大 413 |
| 5 | nonce 首次使用（验签通过后才占用，10 分钟内不可重复） | 401；Redis 不可用时 503 |
| 6 | 「方法 + 原始路径」在应用已授权的接口中 | 403 |

补充说明：

- **IP 白名单**：逗号分隔的 IPv4 / IPv6 地址或 CIDR（如 `203.0.113.7,10.0.0.0/8`），保存时校验格式。按网关看到的**连接对端地址**判断，不信任 `X-Forwarded-For`（可被客户端伪造）；网关前面有负载均衡或反向代理时，对端是代理的地址，白名单应填代理地址或留空；
- 第 6 步放在 nonce 之后，未授权的调用也消耗 nonce，同一请求不能被反复用来探测授权；
- 路径里对字母、数字、`- . _ ~` 的百分号编码（如 `/%6Fpen-api/...`）和 `;`、`\`、`%2e`、`%2f` 等歧义写法，网关直接返回 400；
- 签名使用的路径与查询串须与实际发送的完全一致（URL 编码后的原样）。

### 事件回调

平台向应用的回调地址（`notifyUrl`，http 或 https）主动推送事件。管理员可在开放应用中点「发送测试回调」（`POST /admin-api/open/app/test-notify?id=`）验证对接，事件为 `open.test`；业务模块（交易、支付等）今后经内部接口发送各自的事件。

请求：`POST {notifyUrl}`，`Content-Type: application/json`，请求体：

```json
{"eventId":"7f1c0f6e3c9a4b0e8f2d5a1b9c3e4d70","event":"open.test","appKey":"ccloud-open-demo","timestamp":1760000000000,"data":{"message":"ccloud test"}}
```

| 请求头 | 说明 |
|---|---|
| `X-Open-App-Id` | 应用编号（AppKey） |
| `X-Open-Timestamp` | 发送时的毫秒时间戳 |
| `X-Open-Event-Id` | 事件编号，与请求体的 `eventId` 相同；同一事件的所有重试编号不变 |
| `X-Open-Sign` | 签名 |

```
签名串 = X-Open-Timestamp + "\n" + X-Open-Event-Id + "\n" + 请求体的 SHA-256（十六进制小写，按收到的原始字节计算）
X-Open-Sign = Base64( HmacSHA256(key = appSecret, data = 签名串) )
```

接收方的处理：

- 返回 **2xx** 视为成功（响应体内容不限）；其他状态码、超时（连接与读取各 5 秒、整体不超过 10 秒）、连接失败都视为失败。不跟随重定向，回调地址须直接返回结果；
- 失败按下表重试，间隔从上一次失败算起；第 6 次重试仍失败即放弃（状态「放弃」），管理员可在回调日志中对失败待重试或放弃的记录点「重新通知」，重试次数清零后立即再发；
- **按 `X-Open-Event-Id` 去重**：网络超时时对方可能已处理但平台没收到应答，同一事件会再次投递，接收方须保证幂等；
- 验签后建议再校验 `X-Open-Timestamp` 在 5 分钟之内，防止他人重放截获的请求（重试时会用新的时间戳重新签名）；
- 重试时使用应用**当前**的回调地址与密钥：修正回调地址、重置密钥后，后续重试随之生效。

| 次数 | 发送时机 |
|---|---|
| 首次 | 事件产生后立即 |
| 第 1 次重试 | 失败后 15 秒 |
| 第 2 次重试 | 再过 1 分钟 |
| 第 3 次重试 | 再过 5 分钟 |
| 第 4 次重试 | 再过 30 分钟 |
| 第 5 次重试 | 再过 2 小时 |
| 第 6 次重试 | 再过 6 小时；仍失败则放弃 |

重试由 XXL-Job 任务 `openNotifyRetryJob` 每 15 秒扫描驱动，实际间隔可能比表中多出至多 15 秒。

回调地址的限制（防止借回调访问内网，SSRF）：只允许 http / https；发送时解析域名，解析结果为回环、内网（私有）、链路本地、组播、未指定地址时拒绝；云元数据地址（`169.254.169.254`、`fd00:ec2::254` 等整个 `169.254.0.0/16` 段，含 IPv4 映射写法）在任何配置下都拒绝。仅本地开发与 docker 联调（回调接收方在本机）会通过配置项 `ccloud.open.notify.allow-private-address=true` 放开前者，**生产环境必须保持 `false`**。

Java 验签示例（与平台的 `OpenNotifySigner` 同一算法）：

```java
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.util.Base64;
import java.util.HexFormat;

public final class OpenNotifyVerifier {

    /** body 为收到的请求体原文，其余参数取自同名请求头；返回 true 表示签名正确 */
    public static boolean verify(String appSecret, String timestamp, String eventId, byte[] body, String sign)
            throws Exception {
        String bodyHash = HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(body));
        String stringToSign = timestamp + "\n" + eventId + "\n" + bodyHash;
        Mac mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(appSecret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        byte[] expected = Base64.getEncoder().encode(mac.doFinal(stringToSign.getBytes(StandardCharsets.UTF_8)));
        // 恒定时间比较，并建议另外校验 timestamp 距当前不超过 5 分钟、eventId 未处理过
        return MessageDigest.isEqual(expected, sign.getBytes(StandardCharsets.UTF_8));
    }
}
```

### 演示应用与完整调用示例

初始化数据带一个演示应用：AppKey `ccloud-open-demo`、密钥 `ccloud-open-demo-secret`（租户 1），已授权接口 `GET /open-api/member/user/get`（按手机号查询会员基本信息，手机号脱敏）。**生产环境必须重置密钥或删除该应用。**

```bash
APP_KEY=ccloud-open-demo
APP_SECRET=ccloud-open-demo-secret
GW=http://127.0.0.1:28080
PATH_=/open-api/member/user/get
QUERY='mobile=13800138000'
TS=$(python3 -c 'import time; print(int(time.time() * 1000))')
NONCE=$(uuidgen)
BODY_HASH=$(printf '' | openssl dgst -sha256 | awk '{print $NF}')      # 没有请求体：空字节的摘要
SIGN=$(printf 'GET\n%s\n%s\n%s\n%s\n%s' "$PATH_" "$QUERY" "$TS" "$NONCE" "$BODY_HASH" \
  | openssl dgst -sha256 -hmac "$APP_SECRET" -binary | base64)

curl -s "$GW$PATH_?$QUERY" \
  -H "X-Open-App-Id: $APP_KEY" -H "X-Open-Timestamp: $TS" -H "X-Open-Nonce: $NONCE" -H "X-Open-Sign: $SIGN"
# {"code":0,"data":{"id":1,"nickname":"演示会员","avatar":"","mobile":"138****8000","levelName":"白银会员","point":192,"status":0},"msg":""}
```

返回的会员信息只含基本资料，手机号脱敏为 `138****8000`；手机号未注册返回业务错误码。调用记录可在管理后台 开放平台 → 调用日志 中查到（调用日志由提供接口的业务服务经 Redis Stream 发给 open，通常几秒内可见；被网关拒绝的调用不入表，网关打 warn 日志），默认保留 30 天。

## 内部接口 rpc-api

`/rpc-api/**` 只供服务之间经 Feign 直接调用（不经网关），经网关访问一律返回 403。Feign 调用自动透传租户与登录身份：

| 请求头 | 内容 |
|---|---|
| `X-Login-User` | Base64(UTF-8(JSON(LoginUser)))，含用户编号、用户类型、租户、客户端、授权范围、过期时间 |
| `X-Login-User-Sign` | Base64(HmacSHA256(内部签名密钥, `X-Login-User` 的值 + "." + `X-Timestamp`)) |
| `X-Timestamp` | 毫秒时间戳，业务服务只接受 5 分钟内签发的身份 |
| `X-Tenant-Id` | 租户编号 |

网关写入的也是这四个头。外部请求携带的 `X-Login-User`、`X-Login-User-Sign`、`X-Timestamp` 会被网关剥离。

## 令牌缓存与吊销

以下操作会作废该用户的全部访问令牌与刷新令牌，所有客户端需重新登录：

- 管理员：本人修改密码（含当前会话）、忘记密码重置、被管理员重置密码、被禁用、被删除；
- 会员：修改密码、忘记密码重置。

网关缓存令牌校验结果 60 秒。经本网关实例登出会立即清除该令牌的缓存；在其他网关实例登出，或修改密码、禁用账号吊销令牌后，
各网关实例最多还会放行 60 秒。缓存时长由 Nacos `ccloud-gateway.yaml` 的 `ccloud.security.token-cache-ttl` 调整（需重启网关）。
